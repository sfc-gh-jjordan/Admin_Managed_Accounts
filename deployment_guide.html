1. What you are deploying

A Streamlit in Snowflake application in your main account EIGHTY451 (Azure East US 2) that lets EIGHTY451 account administrators onboard, offboard, and audit human users across all Snowflake accounts in your organization. Changes to managed accounts are made by a scheduled worker that calls each account’s Snowflake SQL API using a dedicated key-pair service user.

ComponentWherePurpose
ACCT_ADMIN_DB databaseEIGHTY451Account registry, role catalog, operation queue, inventory, audit history
Worker procedures WORKER.EXEC_<ACCOUNT_ID>EIGHTY451One per managed account, each bound to that account’s key and network rule only
TasksEIGHTY451Dispatch approved work (5 min), reconcile drift (6 h), purge credential links (hourly)
Streamlit app APP.MANAGED_ACCOUNTS_ADMINEIGHTY451Admin UI; available only to ACCOUNTADMIN users
Service user SVC_ACCT_ADMIN + authentication policiesEach managed accountKey-pair identity for the SQL API; MFA policies for customer and internal admin users

Legend used in this guide: EIGHTY451 run in your main account   Managed account run in each managed account   Workstation run on an administrator’s machine

2. Prerequisites

Access

  • A user with ACCOUNTADMIN in EIGHTY451.
  • ORGADMIN (or GLOBALORGADMIN) enabled in EIGHTY451 for organization account discovery.
  • ACCOUNTADMIN access to each managed account, or a delegate who can run the per-account bootstrap script.
  • At least two EIGHTY451 ACCOUNTADMIN users who will use the app (one to request, a different one to approve).

Tools

  • Snowflake CLI (snow) or SnowSQL, connected to EIGHTY451, for uploading files with PUT.
  • openssl for generating key pairs.
  • git to retrieve the code.

Decisions to make before you start

DecisionDefaultNotes
Pilot (sandbox) managed account—Deploy end to end against one non-production account first.

Allowed roles per account—Roles that customer CSVs may assign. Privileged roles are always blocked. A CSV may also name a role that is not yet catalogued; it is created on approval (see section 13).

Secure channel for password / MFA links—Links are single use and expire after 12 hours.

4. Central setup (EIGHTY451)

EIGHTY451 Run as ACCOUNTADMIN in a Snowsight worksheet or with the CLI.

  1. Run sql/01_central_setup.sql. It first confirms it is running in EIGHTY451 / AZURE_EASTUS2 and stops otherwise. It creates the warehouse ACCT_ADMIN_WH, the application roles, the database ACCT_ADMIN_DB with schemas CONTROL, APP, WORKER, NET, SECRETS, and the code stages.
  2. Run sql/02_control_tables.sql to create the registry, queue, inventory, audit tables, and views. Fresh installs include the IMPORT_BATCHES.NEW_ROLES and OPERATIONS.DEPENDS_ON columns used by CSV role creation, so sql/08 is not needed.
snow sql -c <eighty451_connection> -f sql/01_central_setup.sql
snow sql -c <eighty451_connection> -f sql/02_control_tables.sql
Check: SHOW SCHEMAS IN DATABASE ACCT_ADMIN_DB; returns the five schemas, and SHOW TABLES IN SCHEMA ACCT_ADMIN_DB.CONTROL; lists the control tables.

5. Discover organization accounts

EIGHTY451 Run sql/03_org_account_discovery.sql as a user holding both ORGADMIN and ACCOUNTADMIN.

The script reads SHOW ACCOUNTS LIKE 'EIGHTY451%_EXT', excludes EIGHTY451 itself, and seeds CONTROL.CUSTOMER_ACCOUNTS with each account’s locator, region, SQL API host, and JWT account identifier. New accounts are added disabled with status NOT_BOOTSTRAPPED; nothing can be executed against them yet.

Before running: edit the SHOW ACCOUNTS LIKE pattern in sql/03 so it matches the managed accounts you want to register. Only accounts returned by that statement are seeded.

The derived SQL_API_HOST is lowercase with underscores replaced by hyphens (<org>-<account>.snowflakecomputing.com). JWT_ACCOUNT_IDENTIFIER is <ORG>-<ACCOUNT> in uppercase with underscores kept.

Re-run this script whenever accounts are added to the organization. It updates descriptive fields but never overwrites an account’s verified host or identity.

Review the output and, if needed, correct DISPLAY_NAME before continuing. The ACCOUNT_ID column is the short key used throughout the remaining steps.

6. Connect a managed account

Repeat this section for each managed account, starting with your pilot account. Each account gets its own key pair.

6.1 Generate a key pair

Workstation

Use the ACCOUNT_ID of an account with BOOTSTRAP_STATUS = 'NOT_BOOTSTRAPPED' in CONTROL.CUSTOMER_ACCOUNTS.

ACCT=CPG_ACME   # the ACCOUNT_ID from the registry
openssl genrsa 2048 | openssl pkcs8 -topk8 -inform PEM -out sqlapi_${ACCT}.p8 -nocrypt
openssl rsa -in sqlapi_${ACCT}.p8 -pubout -out sqlapi_${ACCT}.pub
Treat the .p8 file as a credential. Store it only in the Snowflake secret created in step 6.3, then delete it from the workstation. Never commit it to source control.

6.2 Bootstrap the managed account

Managed account Open sql/04_target_account_bootstrap.sql, paste the body of sqlapi_${ACCT}.pub (without the BEGIN/END lines) into the RSA_PUBLIC_KEY placeholder, and run it as ACCOUNTADMIN in the managed account.

The script creates:

  • Database ADMIN_POLICIES with authentication policies CPG_HUMAN_MFA_V1 (customer users) and INTERNAL_ADMIN_MFA_V1 (84.51 admins), both requiring password plus MFA, and SQLAPI_SERVICE_V1 (key pair only).
  • Service user SVC_ACCT_ADMIN (TYPE = SERVICE) with ACCOUNTADMIN and the optional ACCT_USER_ADMIN role.

The script runs SHOW AUTHENTICATION POLICIES ON ACCOUNT; first so you can review any existing account-level policy. Never weaken a stronger existing policy. The app attaches its policies to managed users only and does not change account-level settings.

Network policy for the service user (required)

The script now creates network rule ADMIN_POLICIES.POLICIES.CENTRAL_EGRESS and network policy SQLAPI_SERVICE_NP, and attaches the policy to SVC_ACCT_ADMIN. Replace the <<central egress CIDRs>> placeholder before running, or the script fails.

EIGHTY451 Get the egress ranges from the central account:

SELECT value:"ipv4_prefix"::VARCHAR  AS ip_cidr_range,
       value:"effective"::TIMESTAMP  AS effective_date,
       value:"expires"::TIMESTAMP    AS expiration_date
FROM TABLE(FLATTEN(INPUT => PARSE_JSON(SYSTEM$GET_SNOWFLAKE_EGRESS_IP_RANGES())));

Managed account Put the returned ip_cidr_range values (quoted, comma-separated) into VALUE_LIST. Egress ranges have expiration dates, so review them periodically.

The bootstrap does not create shared customer roles yet (section 6 of the script is marked TODO). Either create them here and add them to the role catalog, or let a CSV import request them: roles with no catalog entry are created on approval (empty, granted to SYSADMIN, catalogued as default-eligible). This needs EXEC_ROLE = ACCOUNTADMIN.

From the script output, record:

  • RSA_PUBLIC_KEY_FP from DESC USER SVC_ACCT_ADMIN (starts with SHA256:).
  • The account locator returned by CURRENT_ACCOUNT(); it must match EXPECTED_ACCOUNT_LOCATOR in the registry.

6.3 Store the key and register connectivity

EIGHTY451 In a worksheet, using role ACCT_ADMIN_BOOTSTRAP:

USE ROLE ACCT_ADMIN_BOOTSTRAP;

CREATE OR REPLACE SECRET ACCT_ADMIN_DB.SECRETS.SQLAPI_KEY_CPG_ACME
  TYPE = GENERIC_STRING
  SECRET_STRING = '-----BEGIN PRIVATE KEY-----
...contents of sqlapi_CPG_ACME.p8...
-----END PRIVATE KEY-----';

UPDATE ACCT_ADMIN_DB.CONTROL.CUSTOMER_ACCOUNTS
   SET PUBLIC_KEY_FP = 'SHA256:...from step 6.2...',
       SECRET_VERSION = 1,
       REGISTRY_VERSION = REGISTRY_VERSION + 1,
       UPDATED_AT = CURRENT_TIMESTAMP()
 WHERE ACCOUNT_ID = 'CPG_ACME';

Replace CPG_ACME in the secret name and the WHERE clause with the account’s ACCOUNT_ID.

Workstation Upload the worker code as ACCT_ADMIN_WORKER. The generated worker procedure imports sqlapi_client.py from the stage, so this must be done before registering connectivity:

snow sql -c <eighty451_connection> --role ACCT_ADMIN_WORKER -q "

Make sure the files are not compressed and are uploaded to the root of the stage.

EIGHTY451 Run sql/05_account_connectivity.sql. It creates the generator procedure and then calls it. Edit the 'CPG_ACME' argument in STEP C to your account’s ACCOUNT_ID before running. For later accounts, just call the procedure:

This creates a network rule that allows only that account’s SQL API host, an external access integration bound to that rule and secret, and the worker procedure WORKER.EXEC_CPG_ACME. The account status becomes CONNECTIVITY_READY.

7. Deploy the worker and tasks

EIGHTY451 The worker code was uploaded in section 6.3. Run sql/06_worker_dispatch_and_tasks.sql as ACCT_ADMIN_WORKER. It creates:

  • WORKER.DISPATCH – processes queued operations or reconciliation across enabled accounts.
  • WORKER.RUN_ACCOUNT – on-demand run for a single account (used by the app).
  • Tasks DISPATCH_TASK, RECONCILE_TASK, PURGE_HANDOFF_TASK. They are created suspended, and the script then resumes them.

The end of the script also runs the preflight and enable steps below for one account. Edit 'CPG_ACME' in those statements before running.

Because the tasks are resumed here, reconcile runs against every enabled account from this point on. Dispatch only runs operations that have been approved. To keep tasks paused until the pilot passes, comment out the three ALTER TASK ... RESUME lines and resume them in section 11.

7.1 Preflight each connected account

USE ROLE ACCT_ADMIN_WORKER;
CALL ACCT_ADMIN_DB.WORKER.RUN_ACCOUNT('CPG_ACME', 'PREFLIGHT');

The preflight makes no changes. It signs in to the managed account and confirms the account locator, service user, and execution role match the registry.

Expected: the result contains "ok": true and CUSTOMER_ACCOUNTS.BOOTSTRAP_STATUS becomes VERIFIED. If not, see Troubleshooting.

7.2 Enable the account

Only after a successful preflight:

SELECT ACCOUNT_ID, BOOTSTRAP_STATUS, IS_ENABLED
FROM ACCT_ADMIN_DB.CONTROL.CUSTOMER_ACCOUNTS
WHERE ACCOUNT_ID = 'CPG_ACME';   -- expect VERIFIED

UPDATE ACCT_ADMIN_DB.CONTROL.CUSTOMER_ACCOUNTS SET IS_ENABLED = TRUE WHERE ACCOUNT_ID = 'CPG_ACME';

You can also enable the account from the Account registry page in the app (section 10.1).

Before uploading, confirm these versions are available in your account; if not, change the pins. The Streamlit version must support st.navigation, st.segmented_control, st.pills, and horizontal containers.

EIGHTY451 Query INFORMATION_SCHEMA.PACKAGES to see the versions the Snowflake Anaconda channel offers in your account. The commented block at the top of sql/07 contains this query and a query that prints the environment.yml currently on the stage.

SELECT package_name,
       MAX_BY(version, TRY_TO_NUMBER(SPLIT_PART(version,'.',1))*1e6
                     + TRY_TO_NUMBER(SPLIT_PART(version,'.',2))*1e3
                     + TRY_TO_NUMBER(SPLIT_PART(version,'.',3))) AS latest_version,
       ARRAY_AGG(DISTINCT version) WITHIN GROUP (ORDER BY version DESC) AS all_versions
FROM ACCT_ADMIN_DB.INFORMATION_SCHEMA.PACKAGES
WHERE language = 'python'
  AND package_name IN ('streamlit', 'pandas', 'snowflake-snowpark-python')
GROUP BY package_name;

EIGHTY451 Run sql/07_app_commands_and_streamlit.sql as ACCT_ADMIN_OWNER, then run its final grant as ACCOUNTADMIN if the owner role cannot grant it. This creates:

  • APP.COMMAND – the only path the app uses to change anything. It confirms the caller holds ACCOUNTADMIN on every call.
  • Streamlit app APP.MANAGED_ACCOUNTS_ADMIN on the warehouse runtime (RUNTIME_NAME = 'SYSTEM$WAREHOUSE_RUNTIME'), granted to the ACCOUNTADMIN role only.
The runtime is set explicitly because, since BCR bundle 2026_06, leaving out RUNTIME_NAME defaults to the container runtime, which ignores environment.yml.

9. Assign admin duties

Every app user must hold ACCOUNTADMIN in EIGHTY451. Within that group, duties are assigned in CONTROL.ADMIN_AUTHORIZATIONS so that requesting and approving are performed by different people.

PermissionAllows
CAN_VIEWOverview, inventory, operations, audit
CAN_OPERATEUpload CSVs, request disable/re-enable, password/MFA links, internal admin requests
CAN_APPROVEApprove customer operations (including CREATE_ROLE from CSV imports), retry/cancel, pause accounts, view secure handoff links
CAN_PRIV_APPROVEApprove internal ACCOUNTADMIN grants; edit registry and role catalog
-- List eligible users
SHOW GRANTS OF ROLE ACCOUNTADMIN;

INSERT INTO ACCT_ADMIN_DB.CONTROL.ADMIN_AUTHORIZATIONS
  (ADMIN_USER, ACCOUNT_ID, CAN_VIEW, CAN_OPERATE, CAN_APPROVE, CAN_PRIV_APPROVE)
VALUES ('ADMIN_ONE', '*', TRUE, TRUE, FALSE, FALSE),
       ('ADMIN_TWO', '*', TRUE, TRUE, TRUE,  TRUE);

Use '*' for all accounts or an ACCOUNT_ID to scope a permission. Self-approval is always refused. Check the assignments with SELECT * FROM ACCT_ADMIN_DB.CONTROL.ADMIN_AUTHORIZATIONS;.

For the internal ACCOUNTADMIN workflow, add eligible 84.51 employees to CONTROL.INTERNAL_ADMIN_ROSTER with ELIGIBILITY_STATUS = 'ELIGIBLE' and EMAIL_VERIFIED = TRUE after review.

ACCOUNTADMIN membership is checked against SNOWFLAKE.ACCOUNT_USAGE.GRANTS_TO_USERS, which has some latency. A newly granted administrator may need to wait before the app recognizes them. Only direct grants of ACCOUNTADMIN to the user are recognized.

11. Go live

Go-live checklist

  • Pilot scenarios 1–11 passed.
  • At least two app users with approver permission.
  • Each enabled account shows BOOTSTRAP_STATUS = VERIFIED.
  • Role catalog and email domains set for each enabled account.
  • All local .p8 private key files deleted.
  • Secure link delivery channel agreed with customers.

13. Creating roles from a CSV import

A CSV row may name a role_name or default_role that has no entry in the account’s role catalog. Instead of rejecting the row, the app requests the role’s creation in the managed account as part of the same batch.

13.1 How it works

  1. Import and review. The row is valid and its findings show role_name: <ROLE> will be created (new role). The page lists every new role under Roles to be created. The operator must tick the confirmation before Submit for approval is enabled.
  2. Submit. APP.COMMAND re-checks every role on the server, then creates one CREATE_ROLE operation per new role, plus the usual user operations. Each user operation records the role operations it needs in OPERATIONS.DEPENDS_ON.
  3. Approve. A user with CAN_APPROVE (not the requester) approves the CREATE_ROLE operations along with the user operations on the Approvals page. Rejecting a CREATE_ROLE operation also cancels the user operations that depend on it.
  4. Execute. The worker runs CREATE_ROLE first. It creates the role with no privileges, grants it to SYSADMIN, reads it back, and adds it to the role catalog as active, STANDARD and default-eligible, with review notes naming the batch, requester and approver. User operations wait in QUEUED until their roles exist, then grant them as usual.

Statements the worker runs in the managed account (as ACCOUNTADMIN):

SHOW ROLES LIKE 'DEMO\\_ANALYST\\_ROLE';
CREATE ROLE IF NOT EXISTS "DEMO_ANALYST_ROLE" COMMENT = 'managed by acct-admin op 1a2b3c4d';
GRANT ROLE "DEMO_ANALYST_ROLE" TO ROLE "SYSADMIN";

13.2 Rules and safeguards

RuleBehavior
Execution roleThe account’s EXEC_ROLE must be ACCOUNTADMIN; otherwise the CREATE_ROLE operation is BLOCKED and its user operations are blocked too.
Never createdRoles in BLOCKED_ROLES, Snowflake system roles (ACCOUNTADMIN, SECURITYADMIN, USERADMIN, SYSADMIN, ORGADMIN, GLOBALORGADMIN, PUBLIC), and names that do not match ^[A-Z][A-Z0-9_]{0,254}$.
Disabled catalog entriesA role that is inactive or BLOCKED in the catalog is rejected; a CSV never re-enables it.
Batch limitAt most 10 new roles per batch; extra rows are rejected.
PrivilegesNew roles are empty. Grant data access separately (see Day-2 operations).
Role already exists on the targetIt is added to the catalog (noted as pre-existing) without changing its hierarchy or grants.
Catalog versionAdding the role bumps the account’s catalog version. Pending operations in the same batch stay valid; pending approvals from other batches become stale, as with any catalog edit.
Catalog changed after uploadSubmit is refused (role catalog changed since validation; re-upload).
Check role names carefully. A typo in role_name now creates a new role instead of failing validation. The Roles to be created list and the approver’s review are the safeguards.

15. Uninstall / rollback

Uninstalling does not change users already created in managed accounts, or roles created from CSV imports. Disable or hand over those users first if required. Roles created by the app carry the comment managed by acct-admin op ...; find them with SHOW ROLES in the managed account and drop them only after confirming nothing depends on them.

EIGHTY451 As ACCOUNTADMIN:

ALTER TASK ACCT_ADMIN_DB.WORKER.DISPATCH_TASK SUSPEND;
ALTER TASK ACCT_ADMIN_DB.WORKER.RECONCILE_TASK SUSPEND;
ALTER TASK ACCT_ADMIN_DB.WORKER.PURGE_HANDOFF_TASK SUSPEND;

-- One per account
DROP INTEGRATION IF EXISTS ACCT_ADMIN_EAI_CPG_ACME;

DROP DATABASE IF EXISTS ACCT_ADMIN_DB;
DROP WAREHOUSE IF EXISTS ACCT_ADMIN_WH;
DROP ROLE IF EXISTS ACCT_ADMIN_OWNER;
DROP ROLE IF EXISTS ACCT_ADMIN_VIEWER;
DROP ROLE IF EXISTS ACCT_ADMIN_OPERATOR;
DROP ROLE IF EXISTS ACCT_ADMIN_APPROVER;
DROP ROLE IF EXISTS ACCT_ADMIN_PRIV_APPROVER;
DROP ROLE IF EXISTS ACCT_ADMIN_WORKER;
DROP ROLE IF EXISTS ACCT_ADMIN_BOOTSTRAP;

Managed account As ACCOUNTADMIN:

DROP USER IF EXISTS SVC_ACCT_ADMIN;
DROP ROLE IF EXISTS ACCT_USER_ADMIN;
-- Only if no users still reference the policies:
-- DROP DATABASE IF EXISTS ADMIN_POLICIES;

To disconnect a single account without uninstalling, pause it in the app, then drop its integration and secret and set IS_ENABLED = FALSE.
